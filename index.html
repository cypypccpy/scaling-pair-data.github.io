Scaling Pair Data for Embodied Intelligence

The hand is the instrument of instruments. — Leonardo da Vinci

数据对于具身是一个非常重要的部分，但是怎么 scaling 数据，需要 scaling 什么样的数据，仍然是一个值得探究的问题。我们新发布 Psi-R2.5 模型，通过对人类数据的不断清洗和优化，明确了我们需要什么样的数据和相关属性，对模型训练有了一些新的理解。下面从数据的角度给大家分享一下最近的进展。

Chapter 1

1. Psi-R2.5: Scaling Quality, Not Just Size

我们最新一代的 R2.5 模型采用双层架构，上层作为大脑进行长程任务拆解，将一段长的 instruction 拆解成对应的 subtask，再将其和当前观测输入进下层模型中，输出机器人具体的操作轨迹。我们的上层模型的网络骨干为 QwenVL3.5-4B，下层为 Wan2.2-IT2V-5B，通过同一批预训练数据进行训练。

相比上一代 R2 模型，我们这一代 2.5 主要的核心改变在于数据的质量提升和属性的压缩。在达到 10W 小时后，我们对全部数据进行了一个大的 review，而不是一味地堆量。我们在数据侧做了很多数据信息量的压缩，同时将人类数据到机器人数据的转换通过 scaling 大量的强 pair data 进行提升，并优化了数据质量的定性和定量分析。

同时，对于评测，我们在模型大小脑训练的过程中就将仿真测评引入，将一小部分仿真数据作为预训练的一部分任务加入进去，并在仿真器中直接进行评测。为了衡量基模的能力，我们设定了一个 50 个复杂任务的多任务真机评测集，并在测评时一直随机化各个任务的初始状态，希望能给组合泛化提供一个优质的测评方案。

大家基本都已经清楚，对于具身预训练模型来说，模型架构是最不重要的，两三天就能换一个，决定性影响性能的是数据。具身数据的糟糕程度是其他领域很难想象的。直接将所有数据往模型里面一塞，出来的效果基本相当于我们先训了一个分类器：模型先区分这到底是人类数据还是真机数据，然后再走相应的参数。这就回到了我们用人类数据最核心的点，是怎么让模型把人类数据按机器人数据进行理解。

我们在 R2.5 上的提升主要在两点：一是使用强 pair data 对人类数据和机器人数据进行对齐，二是在语言层面上对数据标注的精度提出更高的要求。在不少工作中，大家会将一些人类和机器人做类似任务，比如都拿同一瓶可乐，这种对应的数据专门标记起来，一起输入进模型里面用作模型训练，希望能学到一些人类数据和机器人数据的对应关系。这种数据我们将其叫做 pair data。

在我们四月发布的 R2 和 W0 中，我们通过在世界模型中做强化学习的方式，可以将人类数据显式转换成对应的机器人数据。这一套流程可以产出带 action、直接能 replay 成功的机器人数据，但是整体流程比较复杂。我们把这种图像上除了本体外其他基本一致、时序上每一帧都能对应上，同时 action 能直接在机器人上 replay 出来的 pair data 叫做强 pair data；而一些只是按照相同任务语义收集的数据叫做弱 pair data。这种强 pair data 本质上是将人类数据的 dynamic 拉到和机器人数据的 dynamic 一个 domain 里面，并且具备可拓展性。

为了更高效地生产这种强 pair data，我们在通过 R2 和 W0 生成了很多高质量的强 pair data 之后，直接训练了一个端到端的数据转换模型，可以实现人类数据和机器人数据的强 pair 直接映射。以往几乎很难采集到高质量的强 pair 数据，基本都是弱 pair 数据，因此无法直接这么对齐。具体的实现方法在后面的章节会有详细介绍。

除了 pair data 以外，还有一个重要的数据属性是语言的标注精度。我们所有的数据都通过 Autolabeling 数据管线进行标注，将每一个分解的原子任务都标注到尽量细致的程度。同时，我们对任务的多样性提出了非常高的要求。我们尽可能地将单个任务的数据量减少，然后通过运维的方法来保证任务的多样性。

很多时候，所谓的数据量很难衡量数据的信息量。试想一下，假设有 10000 小时数据、100 个任务、每个任务 100 小时，它的信息量可能和 100 小时数据、100 个任务、每个任务 1 小时一样。因此，我们会严格压缩同样小时数里面的数据量，尽可能地采集更多的任务，然后在标注阶段对各项原子动作进行精细的标注和审核，保障数据质量。

具身智能不能只做预训练。具身区别于以前非标自动化的核心就在于希望能够把部署成本降至最低，这个是基模在产品上的商业价值所在。因此我们需要训练基础模型，来降低后训练 few-shot 所需的数据量。但是，直接 zero-shot 到客户现场的基础模型，短期以内很难出现，因为客户现场所需的 SKU 和节拍都太定制化了，做过落地的都清楚很难通过别的数据直接做 work。因此，后训练在很长的一段时间内都是必要的组件。

我们开发了一套基于灵巧手的后训练 HIL 与 RL 框架，可以在基础模型的基础上通过非常少量的数据进行微调后完成复杂任务，并在部署时实时收集失败案例，回流数据，提高模型的能力。我们以手机盒装配任务为例，这是一个步骤非常多且要求非常精细的任务，直接 from scratch 用模仿学习训练之后的成功率非常低。而通过我们的 HIL 与后训练 RL 框架，经过几轮迭代之后可以将成功率提高到 99% 的程度，并且只需要花费 1-2 个工作日。该方案同时也部署在了实际的客户现场，来解决各种复杂的 corner case。

2. Scaling Pair Data For Data Alignment

最近，人类数据成为了大多数人的研究对象。但是，如何将人类数据的质量提高到和真实机器人一样，如何将人类数据往机器人数据进行对齐，是使用人类数据最核心的问题。长期以来，人类数据被认为只能用于预训练。大多数研究这方面的工作会先用人类数据进行大规模预训练，接着使用真机数据进行后训练来完成任务。

但是，这种一股脑将人类数据塞进模型里的做法是非常粗暴的。对于某一个固定的评测环境来说，当模型拿高质量数据训练了之后，你再加入其他低质量的数据，反而对模型是有害的。这是因为这时候对于模型来说，低质量数据带来的噪声多于信息量，因此整个效果反而会下降。所以，大部分直接将人类数据加入预训练中的方法难以回答这个问题，因为人类数据的信噪比远低于真机数据。试想一下，假如你采集了一批某任务的人类数据，你拿这个数据都训不出可以完成该任务的模型来，你怎么保证将它加入模型里面会对这个任务有比较大的帮助呢？

因此，大多数人类数据的预训练只能在 high-level 层面上有一些指导，对于真正机器人操作起到的作用非常有限，而具身最关键的就是如何补足操作模态的数据。给我的感觉有点像当时为什么做很多 Zero-Shot Sim2Real 工作的理由：很多时候做 Zero-Shot 而不是 Few-Shot，是为了验证仿真的有效性。如果纯用仿真数据训练出的模型效果不好，大概率这个数据质量或仿真器参数是有问题的。

所以人类数据也是一样的，能直接训练出模型的人类数据，才是质量最高的人类数据，而这种数据才是我们想要拿来做预训练使用的。因此我们认为，对于人类数据预训练来说，搭建一套人类数据质量分析方法，来衡量人类数据的有效性和质量是非常重要的。我们搭建了两个测试方法：一是将数据直接在机器人上进行 replay 轨迹，看能否完成同样的任务；二是用转换完的数据用于后训练，训练完的模型能泛化地完成相关任务。我们使用强 pair data 训练出来的数据转换器，能够直接将人类数据转换成机器人数据，完成数据对齐，并较好地完成上面两个测试。

下面介绍一下业内使用人类数据后训练的一些方法，并给出我们是怎么使用强 pair data 完成这一点的。

虽然是少数，但是学术界也已经慢慢有相关的研究出现。和 sim2real gap 类似，只使用人类数据进行训练的 embodiment gap 也可以拆分成 2 个具体的 gap：

  • Visual Embodiment Gap 人类数据无论是戴着手套，还是裸手，视觉上都会和机器人推理时差得比较大。这里的差异不只是视频里人手和机器人像素上的差别，还包括相机参数、环境变化等。
  • Dynamic Embodiment Gap 人类数据是用人手对物体进行操作，action 通常是通过设备或者视觉算法来获得。它和直接的机器人数据会有三种误差：第一种是手部姿态估计的传感器或者视觉估计误差，第二种是由于人手和机器人关节不一样的运动学误差，第三种是人手的物理参数和机器人物理参数的误差，例如手的摩擦力和机器人的摩擦力不一样。

所有的纯人类数据训练方案基本都是围绕着怎么解决上面两个问题出发的。一部分已有的方案可以总结为对人类数据进行 real2sim 重建到仿真器中，通过轨迹优化或强化学习等方法训练出模型，然后直接 sim2real。这套方案最早是很多做 Sim2Real 工作的延伸，问题有两个：一是 real2sim 技术本身也比较难 scale up，二是还是会面临 sim2real gap 的问题。

还有的工作不走在仿真器中训练模型然后 sim2real 的路线，而是将仿真器用来做类似数据处理的方法来解决 Embodiment Gap。对于 Visual Embodiment Gap，一般的做法是先分割，再 inpainting，然后再把渲染的机器人贴上去。对于 Dynamic Embodiment Gap，类似上面的方法用轨迹优化或强化学习进行处理，最后得到更好的数据来训练一个 policy。

这套方案和上一个方案最主要的区别是，不是在仿真器里训模型再 sim2real，而是用仿真做数据处理，然后再用模仿学习训一个 visuomotor 的 policy。但是同样会面临两个问题：一是 real2sim 技术本身难 scale up，二是图像 inpainting 这一套视觉处理的管线有天生缺陷，很难处理复杂的关系，例如遮挡等。例如一部分工作能把人手换成机械手，但由于深度估计问题，现有的传感器精度无法区分手上的手指与物体的遮挡关系，因此只能保留穿模的视觉效果。而对于模型来说，这些 interaction 的信息才是最重要的。

因此，这个方向基本长期只能做一些比较简单且定制化的任务，以致于很多人认为纯靠人类数据是无法训练出操作比较复杂的模型的。我们团队研究这个方向非常早，基本上所有方法我们都尝试过。最后我们通过用世界模型代替仿真器的方式，通过十万小时规模的人类数据进行预训练，我们的 Psi-W0 可以代替上面方法中仿真器的作用，通过在仿真器里做强化学习的方式，将一条人手轨迹优化成可执行的机器人轨迹，完成人手数据到机器人数据的转换。

本质上这一套方案还是沿用了之前的思想，只不过用世界模型来代替了传统的仿真器，好处是上面的各种 sim2real 和难以 scale up 的问题可以绕过去。到这算是解决了一部分问题，但接下来这一套方案会比较重，又需要 Policy 和 World Model 相互 rollout，又需要强化学习做微调。因此，我们将通过 Psi-W0 转换完的强 pair data 收集起来，将整个流程进行蒸馏，来直接训练人类数据到机器人数据的对齐转换模型。

但是这样还是比较慢。后来我们思考，这一套，包括之前的方法麻烦在于本质上是因为：对于一条已有的人类数据，我们需要凭空造出与其对应的机器人数据，所以才需要各种强化学习、轨迹优化之类的方法来减少 embodiment gap。但是反过来想，那为什么不能从已有的机器人数据出发，造出对应的人类数据呢？机器人数据无论是 visual 还是 dynamic，都是可以直接用的。

如果我们能获得大量的和真机数据匹配的人类数据，然后训一个模型，输入是人手的数据，输出是匹配的机器人的图像和 action，就可以直接做到纯使用人类数据训练模型。想通了上面的逆向思维后，我们逆向使用 Psi-W0，从真正的机器人数据出发逆向生成对应的人手的数据，直接产生高质量的 pair data。

有了这些数据之后，我们可以直接训练一个带 action 的端到端人类数据到机器人数据的转换模型，直接将人类数据往机器人数据进行对齐。这些数据通过我们的模型转换后，再使用我上面说的两种验证方式验证，证明其可行性。从结果来看，经过我们模型转换完的人类数据都能直接在机器人上 replay 或训练模型；有一些特别复杂的任务哪怕无法直接完成，双手的轨迹基本都是大差不差的。

这是因为这个模型本身不是 policy，而是一个带 action 的视频编辑任务，加上整个机器人的动作空间其实是有限的，因此可以更容易地做到 Zero-Shot 的泛化。我们的效果已经可以做到大家任意拿自己的手机、相机等录一段人手操作的视频，都可以通过我们的管线将其转化为各种机器人数据。

3. In-Context Learning

最近，一个非常火的概念是大家希望能够不需要重新训练微调的情况下，让人示范一遍，再将这个轨迹用类似 prompt 的形式加入到模型里面，来引导机器人完成之前完成不了的任务，就是现在很多的 In-Context Learning 或者 Test-Time Training 的方法。

它 make sense 的底层原理在于，直接训练一个可以在 anywhere 做 any task 的模型是很难的，但是训练一个看一遍示范然后能完成任务的模型是更容易的。和大语言模型不一样的是，机器人领域的 context 不是一段机器人的示教视频，而是一段人类示教视频。

但是，借助我们的强 pair data 模型，我们可以轻易地将人类数据转换成对应的机器人数据，更好地作为 prompt 输入到模型里面。因此，我们可以很容易地实现高效的 In-Context Learning，例如下面的视频，In-Context Learning（ICL）使机器人无需更新模型参数，就能基于上下文对新任务实现零样本泛化。机器人不必为每个新任务重新训练，而是通过文本提示或物理提示，推断该做什么、该如何做。更多的细节将在之后放出。
